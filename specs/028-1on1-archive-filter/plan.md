## Summary

Fix `skills/1on1/SKILL.md` so the View One-on-One Detail flow filters out archived items from the `next`, `done`, and `blocked` columns before rendering. `GET /meetings/{id}` returns archived items in these arrays; the website filters client-side. The skill must do the same. The single-column view (`GET /meetings/{id}/items/{section}`) already excludes archived items by API default — no change needed there.

## Phase 0: Research

**Status**: Complete. See [research.md](research.md).

Key finding: `GET /meetings/{id}` does not support `include_archived` — archived items appear in `next`/`done`/`blocked` arrays regardless. Fix must be client-side. The single-column endpoint already excludes archived items by API default; no change needed there.

---

## Phase 1: Design

### 1.1 The Bug (View Detail Flow)

The current View Detail display rules in `skills/1on1/SKILL.md` say:

> The response includes `next`, `done`, and `blocked` arrays directly.
> Display format: each column shows all items from the array.

The fix: after receiving the `GET /meetings/{id}` response, **filter each array to exclude items where `status == "archived"`** before counting and rendering.

### 1.2 Updated Display Rules

Add to the **Display rules** in Flow: View One-on-One Detail, Step 2:

> - **Archived items**: Exclude any item with `status: "archived"` from all three columns before rendering. Items with null/missing status are treated as active.

The item count in each column header (`{count} items`) must reflect the filtered count, not the raw API count.

### 1.3 Single Column Flow — No Change

`GET /meetings/{id}/items/{section}` excludes archived by API default. No code change. Add a comment to the SKILL.md for clarity to prevent future regression.

### 1.4 Edge Case Coverage

Confirm the existing Edge Cases section covers or add:

- All items in a column are archived → column shows "(empty)"
